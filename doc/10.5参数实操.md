## 二、CLI 命令实操记录

### 2.1 用 turtlesim 跑通全部参数命令

```bash
# 终端一：启动模拟器
ros2 run turtlesim turtlesim_node

# 列出所有参数
ros2 param list

# 查看参数描述（类型、约束、最大最小值）
ros2 param describe /turtlesim background_b

# 获取参数值
ros2 param get /turtlesim background_b

# 设置参数值（RGB 改绿色）
ros2 param set /turtlesim background_r 44
ros2 param set /turtlesim background_g 156
ros2 param set /turtlesim background_b 10

# 导出快照（Humble 及之后默认打印到终端，需重定向保存）
ros2 param dump /turtlesim > turtlesim.yaml

# 从快照恢复
ros2 param load /turtlesim ./turtlesim.yaml

# 启动时直接加载参数文件
ros2 run turtlesim turtlesim_node --ros-args --params-file ./turtlesim.yaml
```

### 2.2 用自己写的节点跑通参数命令

```bash
# 默认运行（INFO 级别）
ros2 run example_param_rclpy param_basic

# 启动时指定 DEBUG 级别
ros2 run example_param_rclpy param_basic --ros-args -p rcl_log_level:=10

# 启动时指定 FATAL 级别
ros2 run example_param_rclpy param_basic --ros-args -p rcl_log_level:=50

# 运行中动态修改（另开终端）
ros2 param list
ros2 param set /param_basic rcl_log_level 10

# 导出快照
ros2 param dump /param_basic > param_basic.yaml

# 重启后从快照恢复
ros2 param load /param_basic ./param_basic.yaml

# 启动时加载快照
ros2 run example_param_rclpy param_basic --ros-args --params-file ./param_basic.yaml
```

## 三、踩过的坑

### 3.1 `ros2 param dump` 没生成文件

Humble 及之后版本，`dump` 默认打印到终端，不自动保存。必须用 `>` 重定向：

```bash
ros2 param dump /param_basic > param_basic.yaml
```

## 四、日志级别与数值

| 级别  | 数值                     |
| ----- | ------------------------ |
| UNSET | 0（默认，实际使用 INFO） |
| DEBUG | 10                       |
| INFO  | 20                       |
| WARN  | 30                       |
| ERROR | 40                       |
| FATAL | 50                       |

节点默认级别是 INFO（20），所以默认只打印 INFO 及以上。设成 10 则全打印，设成 50 则只有 FATAL 打印。

日志颜色是 rcutils 自带的，不同级别不同颜色。关闭颜色：

```bash
export RCUTILS_COLORIZED_OUTPUT=0
```

## 五、参数持久化链路

| 操作       | 命令                                  | 效果                 |
| ---------- | ------------------------------------- | -------------------- |
| 临时修改   | `ros2 param set`                    | 立即生效，重启丢失   |
| 保存快照   | `ros2 param dump > xxx.yaml`        | 生成文件，不生效     |
| 运行中恢复 | `ros2 param load`                   | 立即生效，重启仍丢失 |
| 启动时加载 | `--ros-args --params-file xxx.yaml` | 启动时生效，最常用   |

## 六、参数文件的存放位置

### 6.1 `./` 是当前终端所在目录

不是工作空间固定位置，也不是 src。你终端在哪个目录，`./` 就是哪个目录。

### 6.2 工程中的标准位置

参数文件放在功能包的 `config` 或 `params` 目录：

```
example_param_rclpy/
├── example_param_rclpy/
│   └── param_basic.py
├── config/
│   └── param_basic.yaml
├── package.xml
└── setup.py
```

在 `setup.py` 的 `data_files` 里声明，编译后会被安装到：

```
install/example_param_rclpy/share/example_param_rclpy/config/param_basic.yaml
```

launch 文件中用 `get_package_share_directory` 定位：

```python
from ament_index_python.packages import get_package_share_directory
import os

config = os.path.join(
    get_package_share_directory('example_param_rclpy'),
    'config',
    'param_basic.yaml'
)
```

## 七、参数节点代码骨架

```python
import rclpy
from rclpy.node import Node
from rclpy.logging import LoggingSeverity

class ParamBasicNode(Node):
    def __init__(self, name):
        super().__init__(name)
        self.get_logger().info("节点已经启动：%s!" % name)

        # 声明参数
        self.declare_parameter('rcl_log_level', 0)

        # 启动时立即读一次，设置级别
        log_level = self.get_parameter("rcl_log_level").value
        self.get_logger().set_level(LoggingSeverity(log_level))

        # 定时器，周期性重新读参数
        self.timer = self.create_timer(0.5, self.timer_callback)

    def timer_callback(self):
        # 每次回调重新读参数，实现动态修改
        log_level = self.get_parameter("rcl_log_level").value
        self.get_logger().set_level(LoggingSeverity(log_level))

        print(f"========================{log_level}=============================")
        self.get_logger().debug("我是DEBUG级别的日志，我被打印出来了!")
        self.get_logger().info("我是INFO级别的日志，我被打印出来了!")
        self.get_logger().warn("我是WARN级别的日志，我被打印出来了!")
        self.get_logger().error("我是ERROR级别的日志，我被打印出来了!")
        self.get_logger().fatal("我是FATAL级别的日志，我被打印出来了!")

def main(args=None):
    rclpy.init(args=args)
    node = ParamBasicNode("param_basic")
    rclpy.spin(node)
    rclpy.shutdown()

if __name__ == '__main__':
    main()
```

### 7.1 为什么 `__init__` 和回调里都写一遍读参数、设级别

- `__init__` 里写：启动瞬间生效，消除 0.5 秒窗口期
- 回调里写：运行中动态生效，每次重新读参数

两处不是重复，解决的是不同时间点的问题。

### 7.2 当前实现的局限

用定时器轮询实现动态修改，最长有 0.5 秒延迟，且参数变化时节点不会主动收到通知。进阶做法是用**参数回调**，参数一变立即触发，不用轮询。

## 八、参数节点 vs 服务节点横向对比

| 项目         | 服务节点              | 参数节点              |
| ------------ | --------------------- | --------------------- |
| 额外导入     | 服务接口              | 日志枚举              |
| 核心创建     | `create_service`    | `declare_parameter` |
| 是否需要接口 | 需要                  | 不需要，值类型固定    |
| 触发方式     | 客户端请求            | 定时器周期            |
| 回调参数     | `request, response` | 无                    |
| 回调返回值   | 必须有                | 无                    |
| 存属性       | `self.srv`          | `self.timer`        |
| main 结构    | 四步                  | 四步                  |

**通用规律**：所有 ROS2 Python 节点骨架相同——导入、继承 Node、构造函数、回调、main 四步、入口判断。差异只在中间创建什么对象、回调怎么触发、回调里做什么。

**通用规则**：创建的通信对象和定时器对象必须存成属性（`self.xxx = ...`），否则可能被垃圾回收。
